## How to use these files

- Start with [the maintained product requirements](../product-requirements.md) for current planning.
- Use the PDFs to trace why a workflow or interface decision exists.
- Verify old setup instructions against the active root application before following them.
- Do not copy credentials, obsolete integrations, or archived implementation details into current code.
- When a historical requirement is changed, record the current decision in the maintained Markdown documentation.
